# Jambul

Jambul is a Dynamic Island–style app for the MacBook notch, in Swift with AppKit and SwiftUI. This file guides AI coding agents; people find the same rules in `CONTRIBUTING.md`. How the app is put together: @docs/ARCHITECTURE.md

## Ground rules
- **Clean room.** Jambul is MIT-licensed. Never copy code from GPL projects such as boring.notch; take ideas only. Code under MIT, BSD or Apache-2.0 may be adapted, with its notice in `THIRD_PARTY_NOTICES.md`.
- **Deployment target macOS 14.** Newer APIs (Liquid Glass on macOS 26+) go behind `if #available`.
- **Private APIs are allowed** (SkyLight now, MediaRemote later), since Jambul ships outside the Mac App Store, but load them at runtime and fail safe, like `SpaceInspector` does.
- **Measure, don't guess.** Geometry and system-behavior assumptions have been wrong before (the notch's x, where full-screen windows start). Probe the real value on a real Mac first.
- **Performance budget:** idle CPU ≈ 0%, idle footprint < 30 MB, < 60 MB with media playing. Use event-driven system APIs; no polling timers.
- **No lag, no stalls.** Waits past ~100 ms read as lag. An animation that settles before the next one starts reads as a stutter; `MotionTests` guards the hover lift against that.
- **Hover opens, leaving closes, a click toggles.** Closing by click folds the island back to its lifted pill while the pointer stays, and hover leaves it closed until the pointer goes away. The island must never vanish from under a resting pointer (that read as broken), and a click must always visibly do something (a click that only opened read as dead, since hover had already opened it). No swipe gestures: they stalled once the island shrank away from the pointer.

## Keep personal data out of the repository
This repository is public, and everything in it, its history, its pull requests and its issues stays public.
- Never write personal data into tracked files, commit messages, pull requests or issues. That means anyone's usage times or habits read from their own logs, home-folder paths, private email addresses, host names, serial numbers, and raw log excerpts, which name the Mac and its user.
- Evidence gathered on someone's own Mac stays in their private notes or in the conversation. A public change describes the behavior and how it was checked.
- `scripts/setup.sh` installs git hooks that scan every commit, commit message, merge and push with `scripts/scan.sh` (Jambul's own rules, gitleaks' token rules, and private patterns kept outside the repository). CI runs the same scan on every push, on each pull request's title and description, and over the whole history daily. Never bypass the hooks with `--no-verify`. If the scan flags something, remove it; add an exception only when it is clearly neither personal nor secret.
- Nothing scans review comments or issues, so check those yourself before posting.
- **No AI attribution.** Never credit an AI tool as an author: no co-author trailer and no "generated with" footer in commits, pull requests, issues, releases or files, and never commit as an AI tool. `.claude/settings.json` turns Claude Code's own attribution off, and the scan refuses the usual forms.

## Build & run
- `./scripts/setup.sh` once per clone, and again whenever `.githooks/` changes: it installs the git hooks.
- `./scripts/run.sh` builds with Xcode and relaunches the app. It sets `DEVELOPER_DIR`, so `xcode-select` may still point at the Command Line Tools.
- `Jambul.xcodeproj` is generated by XcodeGen from `project.yml`: change settings there, then run `xcodegen generate`. `Jambul/` is a synchronized folder, so new files need no project changes.
- SwiftUI previews of the island states sit at the bottom of `Island/IslandView.swift`; the "Hover" preview is interactive.
- `./scripts/test.sh` runs the unit tests (Swift Testing, hosted in the app; `AppDelegate` skips its UI under tests) and shows compiler warnings, which an incremental `run.sh` build would hide.
- Debug builds add a Debug submenu to the status item (demo activity, demo peek, 10-second timer, Keep Awake as if on for two hours, each battery peek) for trying presentations on the real notch. They also start a timer at launch with `open --env JAMBUL_START_TIMER=<seconds> build/DerivedData/Build/Products/Debug/Jambul.app`, for measuring a running countdown. Quit Jambul first (`pkill -x Jambul`): `open` only brings a running app forward, and the variable never arrives.

## Changes and pull requests
- Never push to `main`. Work on a branch and open a pull request; CI (build, unit tests, scan) has to pass, and a maintainer squash-merges it.
- State-machine changes need tests, since pointer paths are hard to exercise by hand.
- Pin each fix with a test that fails once the fix is undone, and check it: revert the fix, run that test, restore.
- Before opening a pull request, have a separate agent review the change read-only, and fix what it confirms.
- Commit messages, pull requests and code comments are in English. A commit's subject says what changed, in the imperative; its body says why.
- User-facing changes get a line in `CHANGELOG.md` under "Unreleased".

## Debugging
- Presentation changes are logged under the `com.debikurnia.Jambul` subsystem: `/usr/bin/log show --last 10m --predicate 'subsystem == "com.debikurnia.Jambul"'`. Use the full path: in zsh, `log` is a shell builtin.
- When someone reports a glitch, read that log (and `processIdentifier == <pid>` for AppKit's own messages) before guessing.
- Jambul's log is short: its lines can be gone after about a day of use, sooner while the Mac is busy, since the unified log's main store is capped at ~500 MB and drops its oldest file first. loginwindow's and RunningBoard's lines and `pmset -g log` reach back about a week.
- loginwindow logs why the screen locked: `kLWLockFromDisplayDim` (display went dark), `kLWLockFromScreenSaverIdleLaunch`, `kLWLockFromDirectLock` (Control-Command-Q).
- Unit tests run in a Jambul test host, which logs under the same subsystem and takes a real "Keep Awake is on" power assertion for 0 s. RunningBoard's launch lines tell the two apart: a test host's identifier ends in a UUID.
- Measure CPU from accumulated CPU time (`ps -o time= -p <pid>` before and after a window of 20 s or more), not ps's `%cpu`, which is a decaying average. The Mac is often in use meanwhile, so drop windows in which the log shows island activity.
